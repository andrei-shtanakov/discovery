### Проверка scope

Матчером **самого maestro**, его же интерпретатором — не копией семантики у нас.
Проверяется по одному воркстриму: ожидаемый набор путей лежит в файле, по строке
на путь.

Шаг 1 — записать ожидаемый набор. Для уже пройденного воркстрима он берётся
фактом, дифом **от merge-base** (ловушка 3); для предстоящего — прогнозом по
плану, руками:

```sh
git diff --name-only \
  "$(git merge-base <base> <evidence-ветка>)..<evidence-ветка>" > /tmp/a1-expected.txt
```

Шаг 2 — сверить его со `scope` из конфига. Скрипт печатает escape'ы и выходит
`1`, если они есть, поэтому его можно ставить в предполётную цепочку через `&&`:

```sh
~/.local/share/uv/tools/maestro/bin/python - project.yaml a1-contract /tmp/a1-expected.txt <<'EOF'
import sys

import yaml
from maestro.scope_gate import find_escapes, normalize

config_path, ws_id, expected_path = sys.argv[1:4]
with open(expected_path, encoding="utf-8") as fh:
    expected = [line.strip() for line in fh if line.strip()]
cfg = yaml.safe_load(open(config_path, encoding="utf-8"))
ws = next(w for w in cfg["workstreams"] if w["id"] == ws_id)
escapes = find_escapes(normalize(expected), ws["scope"])
print(f"{ws_id}: {len(expected)} paths, escapes: {escapes or 'none'}")
raise SystemExit(1 if escapes else 0)
EOF
```

Прогнано на этом репо 2026-08-21 против `project.yaml` в master: чистый набор
даёт `escapes: none` / exit 0, а подмешанный `src/discovery/cli.py` (он вне
scope `a1-contract`) — `escapes: ['src/discovery/cli.py']` / exit 1. Сигнатуры
пиненые: `normalize(paths: list[str])`, `find_escapes(changed_paths: list[str],
scope: list[str])`.

## Ловушки

### 1. Правка `project.yaml` не применяется к `--resume`

**Было (до 2026-08-19):** прогон молча продолжал с персистед scope из `state.db`,
правка выглядела применённой и не была. Стоило двух прогонов; заведено
`maestro#198`.

**Стало (проверено своим прогоном 2026-08-21, `maestro#199`):** персистед-конфиг
по-прежнему **остаётся в силе** — прогон не меняет правила под собой на ходу, —
но молчание убрано: при дрейфе `run` делает fail-closed halt после recovery,
**без флага обхода**, ни одного диспатча. Сравниваются все поля
`Workstream.from_config`, производная ветка и множество id; `scope`/`depends_on` —
без учёта порядка.

**Что делать:** любая правка конфига ⇒ новый прогон с новым run ID. Принять
правку в живой прогон можно только
`maestro workstream-rework <id> --refresh-from <config>` и только для
`description`/`scope`; топология не принимается никак.

### 2. Матчер scope понимает только `**`, `*`, `?`

Любой другой символ трактуется буквально: `tests/test_task_01[23]_red.py` не
совпадает ни с чем. Red-файлы перечислять **поштучно**.

### 3. Ложный escape от текущей ветки вместо merge-base

Диф от текущего `pilot`/`master` включает коммиты, легшие туда **после**
ветвления, и даёт escape там, где его нет. Считать только от `merge-base`.
Проверка, которая врёт, хуже отсутствующей.

### 4. Описание воркстрима — единственный рычаг влияния на генератор

Обязаны быть три блока (готовые формулировки — в `project.yaml` в master):

1. мета-инструкция о формате `spec/maestro-tasks.md`;
2. pre-check линта для кода, который пишет сам агент: red-файл замораживается
   побайтово, и при красном линте RED не подтверждается — **фатально, без
   ретрая**;
3. запрет копировать cross-workstream зависимости в локальную спеку
   (`Depends on` ссылается только на задачи того же файла).

### 5. Остаточные ветки `task/*`

Ветки живут в репо, а не в рабочей копии. Остаточный `task/*` даёт «red написан
в файл, который уже существовал» и фатальный отказ. Чистить worktree, `ws/*`
**и** `task/*`.

### 6. База должна быть рабочей средой до старта

Тулчейн установлен, `uv run pytest` запускается, линт зелёный, входы
завендорены. TDD не может написать красный тест там, где не работает
`test_command`.

### 7. Гейты одобряет человек

`NEEDS_REVIEW` — консенсус Claude + Codex-критика либо эскалация владельцу.
**Ручных правок `state.db` не делать:** они ретроспективно меняют декларацию,
относительно которой прогон уже исполнен, и зелёный гейт после этого доказывает
не тот прогон.

### 8. Вендоренные байты защищены наполовину

`per-file-ignores` спасает только от линтера — `ruff format` про него не знает и
перепишет файл. Нужен `[tool.ruff] extend-exclude` — он и стоит в
`pyproject.toml`. У pyrefly та же ловушка с другой стороны: сам факт появления
конфига переключает его на более строгий пресет, который начинает ругаться на
вендоренный `gate_check.py`, — поэтому там явный `preset = "basic"`. Правка
одного символа уничтожает то, что доказывает copy-integrity.

### 9. Декомпозиция поперёк TDD-цикла (причина J)

Генератор заводит задачу, чей единственный результат — падающий тест. В
TDD-режиме задача **сама** есть цикл red → green, поэтому такая задача не
зеленеет никогда. Чинится инструкцией в описании воркстрима.

### 10. Замороженный чекпойнт фиксирует поверхность своего времени (причина K)

Red-чекпойнт первой арки хардкодил двухфайловый `EXPECTED_SURFACE`, и законное
расширение поверхности его красило. Агент останавливается **правильно** и
запрашивает решение оператора; чинится оператором постфактум, не агентом внутри
прогона.

### 11. Нумерация red-файлов занята предыдущей аркой

Локальные задачи нумеруются с 001 в каждом воркстриме, а
`tests/test_task_001…013_red.py` заняты первой аркой. Любая вторая арка в этом
репо упирается в занятую нумерацию — обходится явными именами
(`test_a2_00N_red.py`, `test_d2_00N_red.py`).

### 12. Закрытый апстрим-issue ≠ установленный фикс

На 2026-08-21 установленный `maestro` был из `ffb5fa5` — коммита **до** мержа
фикса (`f95918f`): признак — в `site-packages/maestro/` не было `config_drift.py`.
Прогон в тот день молчал бы ровно так же, как позавчерашний. Сверять ревизию
установленного тула, а не статус issue.

### 13. Из worktree upstream-сосед недостижим

`../discovery-toolkit` резолвится рядом с worktree, а не с основным чекаутом —
на этом арка потеряла один прогон. Вендорить руками, **на базовую ветку, до
прогона**, и байты брать из дерева коммита, а не из рабочей копии соседа:

```sh
UP=~/labs/all_ai_orchestrators/discovery-toolkit
D=~/labs/all_ai_orchestrators/discovery/src/discovery/contract
COMMIT=$(git -C "$UP" rev-parse HEAD)
for f in customer engineer; do
  git -C "$UP" show "${COMMIT}:.claude/skills/discovery-interview/frames/$f.md" \
    > "$D/frames/$f.md"
done
```

Дальше — дописать строки в `PINNED.txt` (`path sha256`) и расширить
`EXPECTED_SURFACE` в `tools/check_vendor.py`: файл вне манифеста оказывается вне
**обеих** гарантий, а проверка остаётся зелёной.
